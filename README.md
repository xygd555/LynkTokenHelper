# Windows 领克凭据助手

在 Windows 电脑的微信中登录领克小程序，获取登录凭证，可选择仅在本地查看和复制，或登录后自动提交到 Lynk Sign 面板。工具使用原生 WPF 界面，无需安装 Go、浏览器内核或新版 .NET Desktop Runtime。

支持 Windows 10 1903 及以后版本、Windows 11 的 64 位系统，使用系统自带的 .NET Framework 4.8 或兼容版本。目前尚未完成 Windows 10 实机验收。

## 下载与使用

下载 [最新版 EXE](https://github.com/xygd555/LynkTokenHelper/releases/latest/download/LynkSignTokenHelper-windows-x64.exe)，或下载包含说明和许可证的 [ZIP 包](https://github.com/xygd555/LynkTokenHelper/releases/latest/download/LynkSignTokenHelper-windows-x64.zip)。

1. 网页授权登录需要 Lynk Sign 面板 **v1.4.0 或更高版本**；账号密码备用入口继续支持面板 v1.1.0 及以上版本。
2. 双击 `LynkSignTokenHelper-windows-x64.exe`，填写**面板地址**，点击 **“网页授权登录”**。在系统默认浏览器中登录面板，核对当前账号并点击“确认授权”；工具会自动进入主界面。服务器地址、面板账号和密码在同一登录页中；网页授权只需服务器地址，也可填写账号密码后点击旁边的“账号密码登录”作为备用，这里使用面板账号，不是领克手机号。公网使用 HTTPS，内网 HTTP 测试需手动勾选明文传输选项。
3. 首次使用，点击“抓包证书”旁的“安装”，证书安装在当前 Windows 用户中。
4. 打开**同一台 Windows 电脑上的微信**并完成登录，不要停留在扫码或登录页面。
5. 回到工具，点击 **“开始抓取”**，再点击工具里的 **“打开领克小程序”**。已打开领克窗口时，工具会先正常关闭它再重新打开。
6. 等待获取凭据。通常打开已登录的领克小程序后即可自动获取；如果未登录，请登录领克账号。如果仍未获取到，按弹窗提示**退出小程序内的领克账号后重新登录**，不要只关闭窗口。
7. 捕获单个凭据后自动提交并验证。多个凭据需选择；与面板原绑定账号不同或旧账号身份未知时，核对后确认换绑。验证失败会保留面板原凭据，可重试提交或重新抓取。
8. 工具提示保存成功后，回到面板刷新页面即可，**无需再导入 HAR 文件或手动粘贴凭证**。
9. 重要提示需点击“确认”（也可按 Enter）后继续操作；弹窗不会自动消失，Esc 或点击背景不会跳过确认。完成后关闭工具，工具会先取消请求并恢复原代理；不再使用时，可点击“移除证书”。

“打开领克小程序”已在 Windows 微信 `4.1.13.12`、小程序运行时 `2.5.6.25510` 下实测通过，无需创建桌面快捷方式、重新登录微信或操作微信界面。工具不再检查版本号，自动定位实际加载的小程序运行时，核对函数特征和运行时主线程后，临时启用微信内置的本地启动服务；启动完成、失败或取消后关闭服务，并清理临时资源。连接仅使用 `127.0.0.1`，不经过抓包代理，不读取微信登录凭据，也不向面板上传启动信息。运行时未就绪或本地启动服务被占用时，保留 `weixin://launchapplet/` 入口，其可用性取决于微信是否已经登记该小程序。只关闭微信中的“领克汽车”或“领克”窗口，不结束微信进程或其他小程序；检测到多个领克窗口、关闭失败、微信未安装或打开超时时会提示原因。打开期间助手会临时保持在最前端，完成、失败或取消后恢复原来的置顶状态，可正常切换其他窗口。按钮不会自动退出领克账号；若未出现新的登录流量，仍需在小程序内重新登录。

成功打开小程序后，若 10 秒内仍未获取到本次新凭据，会弹窗提示登录领克账号或退出后重新登录；弹窗期间后台仍会继续抓取和提交。上次保留的 Token 不会被误认为本次获取成功；获取新凭据、停止或重新开始抓取、切换服务器或退出后，会取消待显示的提醒。

微信尚未打开时，会提示先打开并登录；启动入口缺失时，会提示安装微信；小程序打开超时，会提示检查微信扫码、登录页面。工具无法仅凭微信进程判断是否已登录。打开失败、提交失败、抓取超时、证书连接异常和工具连接断开等重要提示均需确认；普通成功与复制提示仍使用短提示。

窗口标题和主界面标题会在“领克凭据助手”后显示当前版本号。主界面可查看并复制本次捕获的 Token 和设备 ID；保存成功、提交失败或取消换绑后，本次捕获值仍保留。重新抓取时，收到新凭据后才替换；切换服务器重新登录会清除之前捕获的凭据。

## 仅本地抓包

无需填写面板地址或账号密码，在登录页点击 **“无需登录，仅本地抓包”** 即可进入。安装抓包证书后，登录同一台电脑的微信，点击“开始抓取”和“打开领克小程序”，按提示在小程序中登录领克账号。

此模式只在本机内存中保留捕获的 Refresh Token 和设备 ID，不连接面板、不自动上传，也不提供提交或换绑按钮。捕获后点击“复制 Token”；多个候选凭据可切换查看和复制。停止、完成或退出时照常恢复原代理，关闭工具后不保留凭据。

右上角“登录服务器”可返回登录页；实际发起服务器登录会清空本地捕获值，需要重新抓取后才会提交。仅返回登录页或点击“返回”不会上传凭据。仅本地模式仍需微信和领克服务正常联网，软件更新检查仍按原有设置进行。

## 网页授权登录

- 浏览器已登录该面板时，直接确认授权即可；未登录或需要修改初始密码时，完成对应步骤后会返回授权页。
- 授权请求有效期为 5 分钟，授权码为一次性且有效期为 1 分钟，工具使用 PKCE 校验后兑换独立登录凭证。工具登录有效期为 1 小时，仅保存在内存中；关闭工具或重新登录时尝试撤销，到期后需重新授权。
- 工具授权仅允许读取当前账号信息、提交领克凭据及退出工具登录，不能用于管理用户、读取整份配置或修改面板密码。网页授权流程不向工具传递面板密码或浏览器 Cookie。
- 工具仅在授权期间临时监听 `127.0.0.1` 的随机端口接收浏览器结果，授权完成、取消、超时或退出后关闭。主界面保持原生 WPF，无需安装浏览器内核、注册自定义协议或新增运行环境。
- 等待期间可点击“重新打开授权页”或“取消”；取消后可重新授权或切换到账号密码登录。浏览器无法打开、面板版本不支持及授权过期时会显示需要确认的提示。

## 检查与安装更新

- 工具启动后自动检查 GitHub 上的最新正式版；登录页及主界面底部也保留“检查更新”按钮。检查不会发送面板账号、密码或 Token。
- 发现新版本时显示版本号和发布说明，由用户确认“更新并重启”后才下载；可以选择“稍后”。抓包、提交、网页授权或换绑确认期间暂缓更新提示，手动检查按钮会在操作结束后恢复。
- 下载窗口提供与面板相同的“默认线路”“备用线路 1”“备用线路 2”和“GitHub 源”，默认使用 `https://v4.gh-proxy.org/` 加速，备用前缀分别为 `https://ghproxy.net/`、`https://ghproxy.homeboyc.cn/`。下载失败后可切换线路并点击“重试”；下载期间锁定线路，可随时取消。只对更新文件下载添加加速前缀，版本信息和 SHA256 仍从 GitHub API 获取。下载窗口显示百分比及已下载大小。工具检查下载地址、文件大小、SHA256 和 EXE 版本；校验不通过时不替换当前版本。
- 下载及准备完成后，工具先正常退出内核并恢复代理，再由用户缓存目录中的临时更新进程替换原 EXE、重新打开工具。仍然只分发一个 EXE，无需新增运行环境。
- 更新沿用 `%LOCALAPPDATA%\LynkTokenHelper` 中的证书和状态，无需重新安装证书。重启后需要重新授权或登录，内存中的 Token 不保留；需要备用时请在更新前复制。
- GitHub 无法访问时，自动检查不弹出错误、不影响使用；手动检查会显示需确认的说明。下载失败可以重试，程序目录不可写时请先将工具移到桌面或其他个人目录。文件替换失败会保留旧版；请求启动新版失败时会尝试恢复原 EXE，并提示从原位置重新打开工具。
- 只跟随本工具仓库的正式 Release，不安装预发布版、不降级。升级后使用 GitHub 正式构建中的默认服务器地址（由 `WINDOWS_HELPER_DEFAULT_SERVER` 设置），仍可手动填写其他面板地址。
- 新增更新功能之前的版本需先手动下载一次新版；之后即可在工具内更新。临时更新文件位于状态目录的 `updates` 子目录，超过一天的缓存会在后续启动时清理。

在 Lynk Sign 面板部署环境中配置：

```env
LYNK_HELPER_REPOSITORY=https://github.com/xygd555/LynkTokenHelper
```

仓库地址也支持 `.git` 后缀。面板中的“下载凭证工具”按钮会使用最新版的固定附件地址；发布新版本后无需修改面板链接。容器修改环境变量后需重新创建，单独重启不会加载新值。

## 抓包与恢复

- 内置 Go HTTPS 代理，仅监听 `127.0.0.1`。只解密 `lynkco.com`、`lynkco.com.cn` 及其子域，其他 HTTPS 连接透传。
- 开始抓取前备份 Windows 原代理；完成、取消、超时或退出时恢复。主进程异常退出时，由独立守护进程尝试恢复，下一次启动也会检查。若用户或其他软件修改了代理，则保留其新设置。
- 停电或强制结束所有进程后，可重新运行工具恢复，也可执行 `LynkSignTokenHelper-windows-x64.exe --restore-proxy`。仍无法恢复时，在 Windows“设置 → 网络和 Internet → 代理”中检查手动代理。
- 支持直连和常见 HTTP 手动上游代理。PAC、仅 SOCKS 上游代理、HTTP 与 HTTPS 分别使用不同代理暂不支持，会在修改设置前提示。
- 微信是否使用系统代理、是否信任当前用户证书，需要在具体版本中实测。获取等待时间为 10 分钟；连接计数不代表已获得有效凭据。
- 工具不保存密码、面板会话、领克 Token 或完整抓包文件。本次凭据只在内存中保留，复制内容由 Windows 剪贴板管理。
- 证书、代理恢复信息及内嵌内核缓存统一保存在 `%LOCALAPPDATA%\LynkTokenHelper`（通常为 `C:\Users\用户名\AppData\Local\LynkTokenHelper`），不在 EXE 旁生成文件夹。同一 Windows 用户移动或更新 EXE 时复用该目录及证书，无需重复安装；私钥由当前用户的 DPAPI 加密。抓取期间不要移动或删除该目录。开发排查仍可通过 `--data-dir` 指定其他状态目录。
- EXE 内嵌 WPF 界面和 Go 抓包内核，通过匿名管道通信。工具尚未进行代码签名。

## 本地构建与验证

开发环境需要 Windows、Go（版本见 `go.mod`）、Visual Studio 的 .NET 桌面开发工作负载和 .NET Framework 4.8 开发工具。

```powershell
./build.ps1
./test.ps1
```

默认服务器地址可在构建时预填，软件中仍可修改：

```powershell
./build.ps1 -DefaultServer 'https://sign.example.com'
```

输出为 `dist/LynkSignTokenHelper-windows-x64.exe` 和同名 ZIP。ZIP 包含 EXE、使用说明及许可证。图标、源码和构建资源全部位于本仓库，**构建不依赖面板源码目录**。

`test.ps1` 执行 Go 测试、静态检查和 WPF 交互测试。测试使用虚构凭据、模拟面板及隔离状态目录，不安装证书或启用系统代理。WPF 测试以独立桌面进程启动，会短暂显示模拟界面，需在可交互的 Windows 桌面执行。测试截图输出到 `test-results/wpf-native/`；不同渲染比例截图不等同于多机 DPI 实机验收。

### 跳过小程序兼容性检查的手动测试版

按需执行以下命令生成单独的测试文件：

```powershell
./build.ps1 -SkipMiniProgramCompatibilityChecks
```

输出为 `dist/unchecked/LynkSignTokenHelper-windows-x64-unchecked.exe`。该文件跳过函数特征、模块范围、管理器布局和主线程兼容性拦截，直接沿用现有内部地址尝试调用；不会自动适配新版本地址，可能导致微信或小程序退出，仅供手动测试。实际进程与任务队列可用性、本地服务归属、连接校验和资源清理仍保留。普通构建与 GitHub Actions 默认不启用此模式，正常 EXE 和 ZIP 不会被测试版覆盖。

## 发布新版

工具使用根目录 `VERSION` 中的独立版本号，格式为 `v1.3.6`，修改工具后先更新该文件。

1. 修改工具后更新 `VERSION`，提交代码并推送到 `main` 分支。
2. **推送后自动构建并发布**，发布说明使用此次推送最后一个提交的说明，正式版会设为 **Latest**。
3. 如果 `VERSION` 对应的版本已经发布，本次仍会构建并保存 Actions 产物，但跳过重复发布；需要发布新版时先递增 `VERSION`。

仍可在 **Actions → 构建并发布 Windows 凭据助手 → Run workflow** 手动运行，填写自定义发布说明，可选勾选“标记为预发布版本”。预发布版不会替换正式版下载入口。

工作流执行 Go 测试与静态检查、构建 WPF 程序、核对 EXE 文件版本并发布 Release。Release 标签为 `VERSION` 中的版本号，附件始终使用：

- `LynkSignTokenHelper-windows-x64.exe`
- `LynkSignTokenHelper-windows-x64.zip`

每个版本的 EXE 文件属性和工具界面都会显示对应版本号，固定附件名用于保持下载链接稳定。已发布附件不会被覆盖；自动运行遇到同名 Release 会跳过发布，手动重复发布同名版本仍会报错。

可在 **Settings → Secrets and variables → Actions → Variables** 配置 `WINDOWS_HELPER_DEFAULT_SERVER`，用于编译时预填面板地址。它与面板运行环境中的 `LYNK_HELPER_REPOSITORY` 是两个独立配置。

工作流使用内置 `GITHUB_TOKEN`，无需另建 PAT；本地完整 WPF 交互验证仍应在发布前执行。

## 小程序打开按钮验证

当前微信的普通协议入口会检查进程内的小程序登记集合：微信添加桌面入口时立即登记，删除快捷方式后当前会话中的登记仍保留；重新启动微信后从桌面入口重新建立集合。这解释了“删除后还能打开、重新登录后又失败”的现象。本次直接启动路径不依赖这份桌面入口登记。

打开按钮已在 Windows 微信 `4.1.13.12` 实测通过。常规 `./test.ps1` 使用模拟窗口与启动器验证首次打开、先关闭再打开、多窗口识别、关闭／打开超时、重复点击拦截、进度与错误提示，以及退出时取消未完成操作，不会操作真实微信。WPF 按钮事件通过 Dispatcher 分发，覆盖异步完成后的 UI 状态恢复，并检查打开期间的原生窗口层级、成功／失败／取消后的置顶恢复及原有置顶状态保留。还覆盖新旧凭据识别、提醒取消、确认提示去重与排队、键盘确认与焦点限制，以及最小工作区的弹窗布局。 网页授权测试覆盖 PKCE、回调状态校验、取消与超时、权限限制、网页登录和改密后的返回路径，以及原生登录页的主入口、密码备用入口和授权后自动进入主界面。可运行 `WpfTests.exe --browser-login` 单独检查原生网页登录交互，或运行 `WpfTests.exe --updates` 单独检查更新服务、文件替换和深色更新弹窗。更新测试使用合成发布信息与隔离文件，覆盖四条下载线路、代理跳转、换线重试、下载取消、文件校验、替换失败恢复和抓包期间暂缓提示。可选运行 `WpfTests.exe --updates-download-live` 从 GitHub 读取正式发布信息，通过默认加速线路实际下载并校验一次，随后删除下载文件，不安装更新；该检查需要网络，不属于常规测试。安全软件拦截仍需在实际环境验收。

如需再次验证真实微信，先登录电脑版微信并构建测试程序，再执行交互式验证：

```powershell
Start-Process -FilePath ./test-results/wpf/WpfTests.exe -ArgumentList "--interactive" -WindowStyle Normal -Wait
```
