# 第一轮界面方向预览

本轮只提供静态设计预览，不改变 Windows 软件的界面或业务功能。

用户已选择 **02 深色仪表台**，并要求贴近 Windows 11 的圆角、图标与字体。后续实现和实际窗口验证见 `../DESIGN.md`；本文件保留第一轮方向探索记录。

## 使用任务

用户登录 Lynk Sign 面板后，在同一台 Windows 电脑的微信领克小程序中重新登录。工具准备证书、获取 refresh token 并向面板提交；提交失败时，用户应能直接查看、复制凭据或重试。

每个方向同时展示登录页和主界面。主界面统一选用“抓取完成、原代理已恢复、服务器提交失败”的状态，便于比较必要信息与补救操作。服务器、账号、Token、设备 ID、时间和计数全部为虚构数据，统一维护在 `content.json`。这些预览按钮没有接入功能。

## 三个方向

1. **白色极简工作台**：居中登录表单与通栏工作区。白底、深灰和珊瑚橙，把凭据、复制和提交重试放在连续阅读路径中。推荐此方向，信息直接，视觉负担最小。
2. **深色仪表台**：分区登录与左右工作台。左侧显示抓包状态，右侧处理凭据；石墨黑与浅蓝用于状态和主操作，适合偏好网络工具视觉的用户。
3. **浅色步骤向导**：登录页顶部明确阶段，主界面左侧持续显示证书、获取与提交的进度。暖灰与松绿色降低操作压力，适合首次使用。

每套均保留证书状态、抓取状态、连接与领克请求计数、Token、设备 ID、复制、重新抓取、提交重试、代理恢复和证书移除。证书安装按钮将在证书未就绪状态出现；当前预览展示已安装状态。

## 设计与边界

- 品类为单用途 Windows 桌面凭据工具，优先参考现有原生窗口的任务结构。此前外部参考页面读取失败，未取得标杆真实画面；不声称已完成外部标杆的视觉核验。
- 预览主要依靠排版、明确状态和控件组织，不使用装饰性照片或生成图片，不增加与任务无关的功能。
- 字体优先使用 Windows 自带中文字体；Token 与设备 ID 使用 Consolas。正文和操作文字不小于 14px。
- 本轮为方向探索，不制作动效、响应式布局、业务交互或独立视觉评分。选定方向后再实现完整状态和原生桌面界面，并检查 DPI 缩放。
- 当前构图使用 520×650 登录窗口与 1040×650 主窗口；后续软件是否切换窗口尺寸，在实现时结合现有窗口行为确定。

## 生成

在项目根目录执行：

```powershell
python windows-token-helper/design/round-01/render_previews.py
python "$env:USERPROFILE/.codex/skills/oil-ui/scripts/build_explorer.py" windows-token-helper/test-results/ui-directions/round-01/manifest.json --force
```

生成的 HTML、对比页、截图和检查报告位于 `windows-token-helper/test-results/ui-directions/round-01/`，不提交 Git。三个 HTML 模板各自维护布局，只有虚构内容共用同一份数据。
